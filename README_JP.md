# Frost Studio

Frost Studio は、動画・音声・画像を扱えるデスクトップメディア編集アプリです。Tauri + React + Go + FFmpeg で構成。すべての処理はローカルで実行されます。クラウドアップロードなし、データ送信なし、ソースコード公開の OSS です。

## 技術スタック

| 技術 | 説明 |
| --- | --- |
| **Tauri** | デスクトップアプリのシェルとOS機能との連携 |
| **React** | フロントエンドのUIコンポーネントとエディター状態管理 |
| **JavaScript** | フロントエンドのアプリケーションロジック |
| **Vite** | フロントエンドの開発サーバーと本番ビルド |
| **Go** | ネイティブなメディア書き出し処理のオーケストレーション |
| **FFmpeg / FFprobe** | ローカルでのメディア解析・加工・エンコード・書き出し |
| **Playwright** | ブラウザベースのUI・ワークフローテスト |

## 本アプリの作成理由

市販の動画編集サイトでは、多くの場合、ファイルをクラウドにアップロードして処理します。そのため長時間・高解像度動画は待ち時間が長く、データがどう扱われるか不透明です。このアプリはマシン上で完結する設計で、プライバシーを守りながら快適に編集できます。

## なぜ Rust ではなく Go なのか

ネイティブなメディア処理コンポーネントには、次の理由から Go を採用しています。

- **FFmpeg との連携** — Go の exporter が FFmpeg プロセスを制御し、JSON でデータを受け渡します。
- **並列書き出し** — goroutine により、複数のタイムラインセグメントを扱いやすく並列処理できます。
- **実装の軽量さ** — プロセス制御、ファイル操作、JSON、同期処理に必要な機能を標準ライブラリで実装できます。
- **配布のしやすさ** — Go は単一バイナリをクロスプラットフォーム向けに生成できるため、Windows と macOS の配布・保守を簡素化できます。

Rust も優れた選択肢ですが、このプロジェクトでは次の理由から Go の方が適していると判断しました。

- **重い処理は FFmpeg が担当するため** — 動画のエンコードは FFmpeg が実行するため、細かなメモリ制御や最大限の CPU 性能が主なボトルネックではありません。
- **複雑さを抑えられるため** — 必要な exporter の実装とビルド手順を、過度な複雑さを加えずに構成できます。

## 機能

| 機能 | 説明 |
| --- | --- |
| **Crop** — プレビューをドラッグ、または数値で座標を指定して映像を切り抜き |
| **メディアソース** — 動画・音声・画像をソース一覧に追加 |
| **プレビュー** — 動画・音声・画像をタイムライン追加前に確認 |
| **タイムライン編集** — 切り取り・削除・コピー・貼り付けでメディアセグメントを再構成 |
| **複数ソース対応** — 複数の素材ファイルを1つのタイムラインで組み合わせ |
| **個別ファイル出力** — タイムラインの各項目を個別の出力ファイルで保存 |
| **音声調整** — ボリュームを 0～200% で調整。簡易正規化オプション付き |
| **Crop後の解像度選択** — 元の解像度で出力、または crop 領域の実解像度で出力 |
| **ハードウェアエンコード対応** — NVIDIA・Intel・AMD の H.264 エンコーダを自動検出。利用不可ならCPU処理に自動切り替え |
| **出力進捗表示** — 全体進捗・セグメント別進捗・経過時間をリアルタイム表示 |
| **画像の標準長さ** — 画像素材は5秒のセグメントとしてタイムラインに追加 |

## 操作ログ

操作ログはアプリケーションの WebView の `localStorage` にローカル保存されます。サーバーへアップロードされず、Go exporter からも書き込まれません。

- ログデータのキー: `videoEditor.operationLogs`
- ログ設定のキー: `videoEditor.operationLogSettings`
- 保持されるログの最大数: 500件
- ログビューアーでクリアすると、保存されているログデータも削除されます

Windows では、WebView2 のデータは通常次の場所に保存されます。

```text
C:\Users\<ユーザー名>\AppData\Local\com.frost.videoeditor\EBWebView\Default\Local Storage\leveldb\
```

正確なフォルダは Tauri / WebView2 のバージョンによって異なる場合があります。ログは直接読める `operationLogs.json` ではなく、LevelDB ファイルとして保存されます。

## 出力について

crop は画素を変更するため、動画の再エンコードが必要です。CPU エンコードでは H.264（libx264 -fast -crf 18）で出力。GPU エンコーダが利用可能ならば、高速かつバランスの取れた設定で処理します。4コア以上のマシンでは、最大2つのタイムラインアイテムを並列処理し、CPU 使用率を分散させます。

エクスポート確認ダイアログで **crop後も元の解像度を保つ** をオフにすると、crop 領域の実解像度で出力できます。アップスケールが不要な場合、この設定で高速化・高品質化・ファイルサイズ削減が実現します。

## 使い方

1. 動画・音声・画像の素材を1つ以上選択
2. プレビューで確認し、素材をタイムラインへ追加して並べ替え
3. 必要に応じて crop、切り取り・削除・コピー・貼り付けを実行
4. タイムラインを出力（タイムラインアイテム1つ = 1ファイル）

## FAQ

- **音声・画像ファイルを使えますか？** — はい。音声・画像素材をプレビューし、タイムラインへ追加して書き出せます。画像は5秒の標準長さで追加されます。
- **音声のみを書き出せますか？** — はい。タイムラインセグメントの **音声のみ** ボタンを使用するか、出力確認画面で **音声のみを書き出す** を有効にしてください。
- **字幕に対応していますか？** — 現在は対応していません。字幕編集や字幕の焼き付けには対応していません。
- **タイムラインのズームに対応していますか？** — 現在は対応していません。切り取り、コピー、貼り付け、削除、セグメントの並べ替えが利用できます。
- **ファイルをドラッグ＆ドロップできますか？** — 現在は対応していません。メディア選択ボタンからファイルを選択してください。タイムラインセグメントはドラッグして並べ替えられます。
